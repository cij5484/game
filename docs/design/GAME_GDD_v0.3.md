## 1. 핵심 철학과 Main Reference

**Mobile Portrait Horde Defense Roguelite.** 핵심 판타지는 “플레이어도 미쳐가고 몬스터도 같이 미쳐간다.”이다.

플레이어의 성장을 억제해 난이도를 유지하지 않는다. 강한 빌드는 실제로 수백 마리 적을 쓸어버릴 수 있어야 한다. 난이도는 주로 Horde 수, Enemy Composition, Elite/위험 적, Pressure Wave와 Threat Budget으로 따라온다. Grunt를 HP Sponge로 만드는 방식은 최소화한다.

핵심 레퍼런스는 아래 **두 작품으로 고정**한다. 아래 항목은 우리 게임에서 참고할 설계 축이며 원작의 정확한 수치·해금 레벨을 복제하는 명세가 아니다.

| Main Reference | 참고할 설계 축 | 우리 게임의 재해석 |
| --- | --- | --- |
| Deep Rock Galactic: Survivor | 자동전투, 무기 성장, 카드 희귀도, Overclock, 큰 장점과 대가가 있는 극단적 변형 | 자동 기본무기와 독립 특수무기, 독립 희귀도, 행동을 바꾸는 전설·Overclock |
| 20 Minutes Till Dawn | 업그레이드 트리, 성장 분기, Synergy, Evolution, 매 Run 다른 Build | 투자 방향을 선택하고 조합이 새로운 행동을 여는 성장 구조 |

다른 작품은 [Reference Notes](REFERENCE_UI_NOTES.md)의 과거 비교 자료다. Main Reference를 임의로 늘리지 않는다. 고유 콘텐츠·아트·아이콘·UI는 복제하지 않는다.

## 2. 캐릭터와 Loadout

모든 캐릭터가 공통 마법 2개를 갖는 구조를 폐기한다. 추가 전투 수단은 캐릭터 정체성으로 결정한다.

| 구분 | Marine — 확정 목표 | 향후 Mage — 방향 예시 |
| --- | --- | --- |
| 기본 공격 | 가우스 소총 | Mage 고유 기본 공격 수단 |
| 추가 전투 수단 | **특수무기 최대 2종** | 마법 슬롯 최대 2 |
| 보조 기술 | 스팀팩 | Mage 고유 보조 기술 |
| 필살기 | Marine 고유 필살기와 고유 Gesture | Mage 고유 필살기 Gesture |

Marine 기본 Loadout에서 서리장·연쇄 번개를 제거하는 것은 **향후 구현할 목표**다. 기존 Magic 콘텐츠와 데이터는 폐기하지 않고 마법사 계열용으로 재사용할 수 있게 보존한다. 이번 문서 작업에서 코드의 Magic을 삭제하지 않는다.

기존 공통 “Magic Slot 1→2→3 영구 해금”은 폐기한다. 특수무기를 “보조무기”라고 부르지 않는다. **보조 기술**은 스팀팩 같은 캐릭터 능력을 뜻한다.

## 3. Marine 기본무기와 입력

초기 가우스 소총은 **느린 단발 자동사격**이다. 한 발 한 발이 보이고 “탕…… 탕…… 탕……”의 간격을 느낀다. 초기 일반 Grunt는 기본 소총 한 발에 죽을 수 있도록 공격력·HP·거리·스폰 시간을 함께 조율한다.

- 기본 공격: 자동 발사. Tap 횟수가 발사 주기를 결정하지 않는다.
- 적 Tap: 해당 적 집중 Target.
- 빈 Battlefield Tap: 집중 Target 해제 후 자동 타겟 복귀.
- 초기 공격주기: 현재 200ms보다 훨씬 느린 값. 정확한 값은 향후 Playtest에서 결정한다.
- 초기 상태에 점사를 강제하지 않는다. 점사는 획득 가능한 기본무기 형태 개조 후보다.

후반에는 개조·공용 강화·특수무기로 전혀 다른 화력 체계가 된다. 자동 공격의 입력 원칙은 유지한다.

## 4. 공용 강화

기존 “기본 강화”를 **공용 강화**로 바꾼다. 기본무기뿐 아니라 장착한 특수무기에도 영향을 주기 때문이다.

핵심 종류는 공격력, 공격주기/공격속도, 치명타 확률이다. 계속 반복 획득 가능하며 Character Run Level에도 상한을 두지 않는다. 공용 강화만으로도 어느 정도 진행할 수 있어야 한다.

공용 강화는 기본무기·수류탄·유도 미사일·드론 등 **적용 가능한 모든 공격 수단**에 적용한다. 무기별 coefficient를 둘 수 있다. 예컨대 공속 +20%가 소총의 간격 개선과 수류탄의 재사용시간 감소에 반드시 같은 비율로 적용될 필요는 없다. 무의미한 능력치를 모든 무기에 강제로 붙이지 않는다.

피해·주기·치명 확률의 합산 방식, 무기별 coefficient, 반복 성장의 증분·비용·실용 상한은 상세 디자인 대상이다. 무제한 레벨은 음수 공격주기나 확률 100% 초과를 그대로 계산하라는 뜻이 아니다. 성장 항목이 더 이상 의미 없을 때는 가짜 선택지 대신 적용 가능한 성장으로 Pool을 유지한다. 치명타 피해 배율을 공용 강화 카드로 다시 추가하는 것은 이번 확정 범위가 아니다.

## 5. Level과 Rarity의 완전 분리

**Level = 얼마나 성장했는가. Rarity = 카드의 가치와 드묾.** `Lv5 = 전설` 규칙은 폐기한다.

희귀도 표시는 **일반 / 희귀 / 유니크 / 전설**이다. 내부 ID는 영어를 사용할 수 있다. 같은 공용 강화라도 희귀도별 상승폭이 다를 수 있다. 공격력 일반 +15~20%급은 예시이고, 희귀·유니크는 더 큰 상승, 전설은 극단적 상승 또는 추가 행동이 될 수 있다. 정확한 수치는 미정이다.

기본무기 개조는 최초 획득부터 희귀·유니크·전설일 수 있다. **Lv1 전설 개조가 존재할 수 있다.** 높은 레벨이라고 자동 승급하지 않으며 낮은 레벨이라고 전설을 금지하지 않는다. 전설의 등장 확률은 매우 낮고 Run을 크게 바꾸는 High-roll 요소다.

카드 종류와 희귀도도 별개다. v0.3의 종류는 공용 강화 / 기본무기 개조·강화 / 특수무기 획득·강화 / 보조 기술 강화 / 캐릭터별 마법 강화 / 유물 / 코어 / 특별 카드 등 역할을 드러낸다. 카드 UI는 큰 아이콘, 이름, 짧은 효과와 핵심 숫자, 종류·희귀도 글자, 필요한 레벨 변화 순으로 읽혀야 한다. 색만으로 희귀도를 구분하지 않는다.

## 6. 기본무기 형태 개조

가우스 소총의 **공격 방식**을 바꾸는 성장. 기본 규칙은 한 Run 최대 **3종**, 자유 조합이다. 슬롯 증가 코어는 검토 가능한 예외이며 최종 증가량·상한은 미정이다. 공용 강화·특수무기·보조 기술·마법은 기본무기 개조 슬롯을 소비하지 않는다.

후보: 관통 / 도탄 / 점사 / 다중탄 / 폭발탄 / 고위력 단발·정밀 사격 / 그 외 행동 차이가 큰 개조. 현재 코드의 관통·도탄·다중탄·폭발탄·처형탄 5종은 최종 Pool로 자동 승계하지 않는다. 처형탄을 포함해 새 구조에 맞춰 다시 평가한다.

다중탄+관통+폭발탄이면 각 탄환에 효과가 자연스럽게 함께 적용될 수 있다. 이를 전부 별도 Synergy로 이름 붙이지 않는다.

개조는 반복 투자할 수 있다. 초반 기본 행동 성장 → 중간 행동 변화 → 높은 레벨의 강한 완성형 → **Lv11 이후 숙련 성장**을 허용한다. 여러 개조를 얕게 조합하거나 1~2개에 몰빵하는 선택이 모두 유효해야 한다. 개조별 정확한 분기 레벨과 최종 성장표는 미정이며, §9 특수무기 전용 Lv3/6/15/20 규칙을 자동 복사하지 않는다.

## 7. 전설 무기 변형

전설은 Lv5 도달 보상이 아니라 낮은 확률로 등장하는 **독립적인 강력 카드**다. 항상 기존 카드의 상위호환일 필요가 없다. 큰 장점과 명확한 대가를 함께 허용한다.

| 예시 — 최종 Pool/수치 아님 | 큰 장점 | 가능한 대가 |
| --- | --- | --- |
| 레일건 프로토콜 | 일정 공격마다 Lane을 가르는 강력한 관통포 | 공격속도 감소 |
| 초고속 급탄 시스템 | 공격속도 대폭 증가 | 개별 탄 피해 감소 |

전설 여러 개가 맞물려 “이번 판 미쳤다”는 경험을 허용한다. 전설 간 호환·중첩·슬롯 관계·적용 불가 조건은 구현 전 설계한다. 무조건 한 Run 하나로 제한하거나 자동 보장하는 규칙을 만들지 않는다.

## 8. Marine 특수무기 — 역할과 획득

특수무기는 단순 보조 화력이 아니다. 완성된 Build에서는 특수무기 하나가 기본무기보다 더 많은 DPS를 담당해도 정상이다. 수류탄 50% / 가우스 소총 25% / 미사일 25% 같은 분포도 허용한다.

| 초기 Pool — 확정 | 역할 | 자동 Target 방향 | 의미 있는 성장 |
| --- | --- | --- | --- |
| 수류탄 | 밀집 Horde 광역 처리 | 가장 밀집된 지역 우선 | 피해, 투척 주기, 폭발·탄두 행동 |
| 유도 미사일 | 위험 적·정예·Shield 집중 추적 | 위험 적 / Elite / 집중 Target 우선 | 피해, 발사 주기, 발사 수·추적 행동 |
| 드론 | 지속적인 독립 화력 | 전장을 돌아다니며 독립 Target 처리 | 피해, 사격속도, 기체 수·무장 형태 |

터렛·레이저는 향후 확장 후보이며 현재 Prototype 목표 Pool에는 포함하지 않는다. 무기별 타겟 기준의 충돌 우선순위·재탐색 조건은 상세 디자인에서 정한다. 동일 Smart Target을 세 무기에 복사하지 않는다.

**획득 레벨은 Character Level이다.**

- Character Lv5: 수류탄·유도 미사일·드론 3개 중 첫 특수무기 1개 선택.
- Character Lv10: 이미 선택한 무기를 제외한 나머지 2개 중 1개 선택.
- 일반 Level-Up 카드 선택을 소비하지 않는 **별도 확정 Power Spike 이벤트**다.
- 한 Run 최대 특수무기 2종. 이 슬롯을 기존 공통 Magic 슬롯 해금으로 늘리지 않는다.
- 획득 즉시 유효 표적이 있다면 첫 공격을 빠르게 보여준다.

특수무기는 모두 자동 운용하며 긴 Magic cooldown 방식이 아닌 짧고 반복적인 공격 Cycle을 갖는다. 개별 주기·첫 공격 지연 수치는 미정이다. 획득 이후에만 그 무기의 강화 카드를 일반 Level-Up Pool에 넣는다. 공용 강화와 해당 무기의 고유 강화를 함께 적용한다.

## 9. 특수무기 성장과 전용 선택 이벤트

**Character Level과 각 특수무기 Level은 별개다.** 두 특수무기에 균형 투자하거나 한쪽에 몰빵할 수 있다. 여기의 Lv3/6/10/15/20은 **해당 특수무기의 레벨**이다.

| 특수무기 Level | 목표 경험과 선택 |
| --- | --- |
| Lv1~10 | 설계된 고유 성장 트리 |
| Lv3 | 전용 화면에서 주요 트리 **3개 모두** 제시 → 1개 선택. 나머지 2개는 해당 Run에서 잠김 |
| Lv6 | 선택한 주요 트리 안에서 **A/B 세부 분기** 선택 |
| Lv10 | 1차 완성형 |
| Lv11+ | 숙련 성장 계속 |
| Lv15 | 전용 **초월 개조**: 큰 Pool에서 RNG로 서로 다른 3후보 → 1선택 |
| Lv20 | 전용 **Overclock**: 큰 Pool에서 RNG로 서로 다른 3후보 → 1선택 |
| Lv20 이후 | 성장 계속 가능. 향후 추가 마일스톤 확장 가능 |

Lv3의 모든 트리 공개와 Lv15/20의 랜덤 후보는 다른 규칙이다. 특수무기 획득·마일스톤을 일반 카드 한 줄의 우연한 후보 노출로 대체하지 않는다. 일반 선택과 동시에 발생하거나 여러 레벨을 넘긴 경우 선택을 잃거나 같은 이벤트를 중복 지급하지 않아야 한다. 구체적인 화면 순서·일시정지 전환·후보 부족 처리·각 Pool 내용은 구현 전 상세 UX에서 확정한다.

### 주요 트리 방향 — 명칭·수치 미정

| 무기 | 주요 트리 A | 주요 트리 B | 주요 트리 C |
| --- | --- | --- | --- |
| 수류탄 | 집속탄: 여러 자탄으로 Horde 처리 | 고폭탄: 적은 횟수, 큰 피해·폭발 | 전술탄: 적 모으기·특수 효과, 예: 중력형 |
| 유도 미사일 | 미사일 포화: 다수 표적 | Hunter Killer: 한 강적 집중 | 특수 추적: 관통·재추적·재유도 |
| 드론 | 드론 편대: 여러 경량 드론 | 중무장 Gunship: 적은 기체·강한 화력 | 호위 드론: Marine 기본무기와 동기화 |

수류탄에 드론의 기체 수처럼 무의미한 항목을 붙이지 않는다. 모든 무기에 피해/공속/쿨다운/치명타를 기계적으로 동일 배치하지 않는다.

## 10. Character Level, 후보 생성과 RNG

Run Character Level에는 상한이 없다. 기존보다 Level-Up 빈도를 높인다. 요구 XP와 증가식은 향후 Playtest로 결정하며 현재 코드의 XP식을 목표 수치로 고정하지 않는다.

일반 Level-Up은 기본 3장 중 1장 선택. Pool은 공용 강화, 기본무기 개조·강화, **보유한** 특수무기 강화, 유물·시너지 시스템이 해금한 특별 카드 등이다. 반복 공용 성장과 숙련 성장으로 Pool 고갈을 막는다. Character Lv5/10의 특수무기 획득 선택은 이 일반 선택과 별도다.

이 게임은 **High-Variance Roguelite**다. 원하는 재료·유물·전설이 나오지 않아 실제로 클리어가 불가능한 Run도 허용한다. 반대로 여러 전설·좋은 유물·특수무기 개조·시너지가 함께 맞아 게임이 무너질 정도의 High-roll도 허용한다. 모든 Run의 파워를 평준화하지 않으며 강한 global pity나 soft pity를 넣지 않는다.

유효성 필터는 운 보정과 다르다. 적용 불가능한 카드, 의미 없는 중복, 미보유 장비 전용 카드, 같은 Run에서 잠긴 분기 등 **가짜 선택**은 배제한다. 원하는 Build를 보장하는 것은 아니다. 현재의 “해금 시너지 한 자리 보장/순환”은 v0.3에 자동 승계하지 않으며 강한 pity 철학과 충돌하지 않도록 재평가한다.

## 11. Reroll

기본 시작 **0회**. Run 밖 영구 성장으로 0→1→2→최대 3회 정도 확보할 수 있는 방향이다. Run 안에서는 일회성 아이템·희귀 보상·특정 유물/코어 등으로 추가 획득할 수 있다. 영구 성장의 약 3회는 Run 중 획득을 포함한 총량 상한 확정이 아니다.

Reroll은 귀한 자원이며 무제한 재추첨으로 RNG를 제거하지 않는다. 획득량·비용·적용 화면·동일 후보 재등장 규칙은 미정이다. 현재 코드에 Reroll이 구현됐다는 뜻이 아니다.

## 12. 유물 — Legacy Prototype에서 재설계

현재 구현 8종은 **Legacy Prototype**이며 v0.3 최종 Pool이 아니다: 테슬라 코일, 광전사 인장, 시간 톱니, 최후의 보루, 탄약 복제기, 서리 공진기, 아드레날린 펌프, 긴급 회수 장치. 기존 Lv1~5 효과·3종 한도·정예 보상 방식을 최종 설계로 자동 확정하지 않는다. 데이터와 동작은 이번 작업에서 보존한다.

새 유물은 Lv1부터 강한 존재감이 있고 획득 직후 화면에서 전투 변화가 느껴져야 한다. 핵심 구조는 **Trigger → 큰 Payoff**다. 공격적·Build-changing 효과를 우선하며 단순 공격력 몇 %나 회복 몇 점을 핵심으로 삼지 않는다.

연결 축은 기본무기↔특수무기, 특수무기↔특수무기, 보조 기술↔무기, Target 지정↔화력이다. “수류탄 폭발 → 다음 미사일 즉시 발사”는 방향 예시이며 구현 완료 효과가 아니다. 하나의 유물에 무관한 효과 4~5개를 붙이지 않는다. 방어/회복 중심은 최소화한다.

최종 유물 Pool과 레벨·슬롯·보상 수치는 **특수무기 실제 전투 구조가 구현된 뒤 별도 설계**한다. 연쇄 상호 발동의 무한 재귀·효과 중복은 그 단계에서 명시적으로 다룬다.

## 13. 코어

코어는 **Run 전용 초희귀 규칙 변경 아이템**이다. 일반 Upgrade보다 “이번 Run의 규칙이 바뀌었다”는 효과가 있어야 한다.

방향 예: 기본무기 개조 슬롯 증가 / 유물 슬롯 증가 / Level-Up 후보 수 증가 / Synergy 강화. 현재 코드의 Pool·드롭률·개수 제한을 최종값으로 자동 승계하지 않는다. 정확한 최종 Pool은 v0.3 시스템 구현 후 재검증한다.

Run-only 코어와 Run 밖 영구 재화는 다르다. 기존 영구 재화 **Core 명칭은 폐기**하며 영구 희귀 재화의 새 이름은 미정이다.

## 14. Run 밖 Meta Progression

**중간 정도의 영구 전투력 + 더 큰 Build 확장.** 영구 성장으로 조금 강해지는 것을 허용하지만 압도적인 성장의 주역은 Run 내부 Build다.

후보는 Character Mastery, 소폭 영구 공격력·공속, Reroll 해금, 신규 캐릭터, 기본무기 Variant, 특수무기 Pool, 유물, 전설 개조와 Build Option이다. 캐릭터 영구 스탯은 각 항목 소수 단계로 제한하고 후반 단계의 비용을 크게 올린다. 초반 캐릭터도 후반 콘텐츠에서 사용 가능해야 한다.

Awakening은 장기 방향으로 유지 가능하다. Mastery 등을 충분히 달성하면 큰 수치만 주기보다 캐릭터 메커니즘·보조 기술·필살기의 변화를 제공한다. 정확한 달성 조건·경제·재화명·저장 시스템은 미정/미구현이다. Run 레벨 무제한과 영구 스탯의 소수 단계 제한을 혼동하지 않는다.

## 15. Director와 Early Dopamine

적 능력치를 Character Level에 직접 1:1 비례시키지 않는다. “Player Lv20 → Enemy HP +200%” 같은 구조는 금지한다.

기본 난이도 축: Run 시간 / Encounter Phase / Threat Budget / Spawn Density / Enemy Composition / Elite·위험 적. 예상보다 강한 Build에 Threat Budget이나 위험 적 비율을 조금 조정하는 것은 **향후 Director 옵션**으로 검토할 수 있다. 성장 직후 적 능력치를 즉시 맞춰 올려 Power Spike를 지우지 않는다. Character Lv5/10 특수무기 획득 직후에는 잠시 강해졌다는 체감을 준다.

| 구간 | 목표 |
| --- | --- |
| 초반 | 많은 Grunt가 멀리 보임. 느린 단발 한 발에 한 마리 처치. 성벽 도착까지 충분한 시간 |
| 성장 | 공속·기본무기 개조·첫 특수무기 획득으로 대량 처치가 급격히 증가 |
| 후반 | Build가 전장을 쓸어버리는 동시에 물량·조합·위험도 증가. 죽이는 것보다 더 많이 나오는 압박도 허용 |

느린 초기 소총으로 물리적으로 처리 불가능한 적을 즉시 성벽에 들이붓지 않는다. 화면상 많은 수와 초반 성벽 피해 압박을 분리해서 설계한다. 정확한 초기 수·HP·이동속도·스폰 간격·Threat Budget 수치는 미정이며 현재 tuning은 구현 스냅샷일 뿐이다.

## 16. Portrait Layout, Header와 Build 정보

Portrait / Full-Bleed / 다양한 세로 화면비 / Safe Area 확장 가능성은 유지한다. 화면은 게임 세계로 채우되 정보 Header와 실제 Enemy Spawn 영역을 분리한다.

```text
[ HEADER ]       정보 전용, Build 아이콘 / 일시정지
[ BATTLEFIELD ]  Header 아래부터 먼 적 Spawn → 중앙 교전
[ WALL HUD ]     성벽 / HP / XP·Level / 전투 능력 상태
```

적의 **시각 Spawn Y만 Header 아래로** 배치한다. Logical progress01·이동속도·성벽 도착시간과 Visual Position·Scale은 분리한다. 표시 영역을 줄였다고 논리 이동거리가 짧아지거나 화면비별 난이도가 바뀌면 안 된다. 긴 화면의 여분은 먼 환경 공간으로 흡수하되 적과 정보가 겹치지 않게 한다. 화면비별 실제 레이아웃 수치는 추후 UI 작업에서 정한다.

### Header 아이콘

공용 강화 / 기본무기 개조 / 특수무기 / 유물 / 코어 / 시너지 / 진화·전설 등 **현재 획득한 요소**를 작은 아이콘으로 요약한다. 필요 시 아이콘 안에 Level을 표시한다. 빈 장식 슬롯을 만들지 않는다.

PC Hover 또는 키보드 Focus, 모바일 Tap 시 **이름·희귀도·현재 Level·한 줄 효과** Popup을 표시한다. UI 정보 입력을 집중 Target이나 Gesture로 전달하지 않는다. Battlefield Input과 UI Input의 소유 영역을 구분한다. 모바일에 Hover를 요구하지 않는다. 닫기·Focus 복귀·Popup 중 전투 시간 정책은 상세 UX에서 확정한다.

### Pause → 현재 빌드

Pause 메뉴는 **계속하기 / 현재 빌드 / 다시 시작**을 제공한다. `현재 빌드`는 별도 한눈에 보는 화면을 연다.

상단 요약 예시: Marine Lv27 · 기본무기 개조3 · 특수무기2 · 유물3 · 코어1 · 시너지2 · 전설1. 이는 예시 Run이며 고정 슬롯/보유 제한 선언이 아니다.

카테고리: 공용 강화, 기본무기, 기본무기 개조, 특수무기1·2, 유물, 코어, 시너지, 진화, 전설. 각 항목은 **아이콘+Level / 이름 / 희귀도 / 한 줄 설명 / 현재 실제 효과 수치**를 표시한다. 긴 텍스트 벽 대신 항목 Tap으로 상세 성장 트리·누적 효과를 펼친다. 단순 카드 원문만 표시하지 않고 실제 현재 값을 구분한다.

향후 Build 공유·친구 기록에서 재사용할 수 있는 정보 구조를 목표로 하되 이번에 공유/Backend를 구현하지 않는다. 별도 `전체 강화 목록` 탭도 설계 후보로 기록한다. 현재 Prototype 전체 Upgrade/Weapon/Relic 등을 볼 수 있고 숨은 Recipe·비밀 진화는 발견 정책에 따라 숨길 수 있다. 이것이 비밀 정보를 즉시 공개하는 결정은 아니다.

## 17. 스팀팩, 필살기, Synergy와 Evolution

Marine 보조 기술은 **스팀팩**을 유지하며 향후 Run 성장과 개조를 허용한다. 마법과 동일한 캐릭터 공통 능력으로 바꾸지 않는다.

필살기는 Character-specific Gesture로 발동하는 강력한 사건이다. 기존 Rhythm Game 방식은 폐기 상태를 유지한다. 현재 Marine V는 실제 구현된 Gesture이며 v0.3에서도 캐릭터 고유 입력이라는 원칙을 유지한다. 최종 필살기 효과·성장·Gesture Pool은 상세 디자인 대상이다.

Synergy는 조합이 여는 **새로운 행동**이다. A 피해 +10% 같은 단순 상승이나 자연스럽게 함께 적용되는 탄환 효과를 모두 별도 시너지로 부르지 않는다.

연결 가능성: 기본무기 개조+개조 / 기본무기+특수무기 / 특수무기+특수무기 / 특수무기+유물 / 보조 기술+특수무기. 기존 Recipe는 새 구조에서 재평가한다. Evolution·초월 개조·Overclock은 큰 Build 완성 순간을 제공한다. 비밀 진화·발견 정책은 미래 설계이며 현재 구현으로 표기하지 않는다. 정확한 Recipe, 해금 후 획득 방식, 시너지 후보 보장 여부는 v0.3 상세 설계에서 정한다.

## 20. 미정 사항과 이번 패스의 경계

미정: 느린 소총의 정확한 주기·초기 HP/피해, Level-Up XP식·빈도, 무기별 공용 강화 coefficient, 기본무기 개조 최종 Pool/성장표, 특수무기 트리명·A/B 효과·숙련 증분·초월/Overclock Pool, 독립 전설의 슬롯/중첩, 유물 최종 Pool/성장/한도, 코어 최종 Pool/수치, Reroll 상세, Meta 경제/재화명, Recipe·획득 정책, Header 크기·Popup/Build 화면 상세 UX. 이 목록은 이번 패스의 누락이 아니라 후속 상세 디자인 범위다.
