# GAME GDD v0.2

> **Current Source of Truth — 성장·HUD·호드 강화 패스**
> 기존 `GAME_GDD_v0.1.md`는 과거 설계 기록으로 원문 보존합니다. 현재 게임 규칙은 이 문서와 Technical Spec, `src/game/data/`를 따릅니다. 아래 수치는 모두 prototype tuning이며 플레이테스트 후 변경할 수 있습니다.

## 1. 게임 비전과 성장 철학

모바일 웹 2D Horde Defense + Roguelite. 성벽 위 고정 Marine이 위쪽에서 몰려오는 적을 막고, 처치 → 경험치 → 선택 → 행동 변화로 성장합니다. 핵심은 터치 전투, 빌드 선택, 대규모 군세 정리, 큰 폭의 성장, 조합 발견입니다. 장기적으로 5~6명 친구 간 기록과 빌드 비교를 목표로 합니다.

**“플레이어도 미쳐가고 몬스터도 같이 미쳐간다.”** 레벨업·유물 강화·특성 Lv.5의 쾌감을 억제하여 난이도를 만들지 않습니다. Horde 수, spawn intensity, Runner/Shield/Elite 비중과 조합이 주요 난이도 수단입니다. Grunt를 HP sponge로 만들지 않습니다. 전설 없이도 클리어 가능한 밸런스가 목표이며, 전설은 의도적으로 강력한 판을 허용합니다. 실제 승률과 재미는 사용자 플레이테스트로 판정합니다.

## 2. 현재 구현과 미래 설계 구분

현재: **전투 시뮬레이션 300초 Run**, Marine/가우스 소총/스팀팩, 마법 2종, 적 3종과 Grunt 기반 Elite, 특성 8종, 유물 8종, 희귀 코어 5종, 시너지 3종, 진화 1종, 필살기 1종. 성벽 HP 12,000이며 300초 생존은 승리, HP 0은 패배입니다. Graybox 표현이며 저장·영구 보상·서버는 없습니다.

선택창과 수동 일시정지는 전투 시간을 소모하지 않습니다. 필살기 리듬 구간은 전장/Run 시간이 0.08배로 흐릅니다. 실제 한 판의 벽시계 시간은 5분보다 길 수 있습니다. 재도전은 경험치·특성·확장·유물·진화·타이머를 모두 초기화합니다.

미래 정식 Stage는 약 15분과 중단 후 Resume를 목표로 합니다. 현재 5분 프로토타입과 혼동하지 않습니다. 이후 시스템은 §13에 구분하며 이번 구현에 포함하지 않습니다.

## 3. 한국어 우선 UI

플레이어 기본 언어는 한국어입니다. 이름·설명·마법·유물·시너지·진화 알림·결과·HUD·버튼·안내 문구를 한국어로 표시합니다. 예: 공격속도, 관통, 도탄, 다중탄, 폭발탄, 치명타, 유물, 진화, 필살기, 준비 완료.

**내부 코드 식별자는 영어**를 유지합니다. 예: `id: "penetration"`, `title: "관통"`. 표시 문구는 data 영역과 각 콘텐츠 정의에 두고, CombatScene 곳곳에 흩어놓지 않습니다. 소규모 표시 문자열 관리로 충분하며 다국어 프레임워크는 도입하지 않습니다. 고유명사는 원문 병기가 가능하고 개발용 Debug Overlay는 영어를 허용합니다.

## 4. 전장 / Portrait / Full-Bleed

- 공식 방향은 Mobile Portrait. 9:16, 9:19.5, 9:20, 세로 태블릿에 대응합니다.
- 최상단 먼 전장/Spawn → 중앙 교전 → 하단 성벽/Marine/통합 HUD. 배경은 화면 끝까지 채우며 검은 letterbox를 기본으로 쓰지 않습니다.
- 720×1280은 논리 표현 기준이며 Phaser Scale Manager RESIZE로 대응합니다. 긴 화면의 여유는 먼 환경, 넓은 화면의 여유는 주변 환경으로 흡수합니다.
- 3 Soft Lane `left/center/right`, lane 내부 lateral offset, 논리 `progress01` 0=Spawn/1=성벽. 이동시간·논리 거리·공격 판정은 physical pixel/visual scale과 분리합니다.
- Fake Perspective는 가까워질수록 시각적으로 커집니다. 공격 slot의 deterministic offset은 성벽 앞 겹침을 줄이는 시각 배치이며 피해·도착시각을 바꾸지 않습니다.
- 복잡한 pathfinding, enemy 물리충돌, physics projectile 없이 가벼운 상태 계산과 hitscan을 사용합니다.
- 상단은 획득한 기본·마법·보조 기술 강화 묶음·무기 특성·유물·코어의 기호+레벨 Build Bar만 작게 표시하고 상세 설명은 일시정지에 둡니다. 하단 성벽은 HP·레벨/XP·시간과 스팀팩/서리장/번개/필살기 4칸으로 구성합니다. 스팀팩 단계와 각 능력 진행도·대기·준비 상태를 계속 표시하며 준비 링·색상·한국어 상태로 사용 가능 여부를 명확히 구분합니다. 일시정지는 우측 최상단 작은 아이콘, 미보유 빈 슬롯은 표시하지 않습니다.
- `viewport-fit=cover`, safe-area inset을 반영하되 배경은 Full-Bleed. HUD와 전장 root는 분리합니다.

## 5. 입력 / 기본 전투 / 스팀팩

| 입력                               | 행동                                           |
| ---------------------------------- | ---------------------------------------------- |
| 적 hitbox 밖 전장 Tap / 왼쪽 클릭  | 성벽에 가장 가까운 살아있는 적을 자동 공격     |
| 적 Tap / 왼쪽 클릭                 | 그 명령만 해당 적 우선, persistent lock 없음   |
| ○                                  | 서리장 즉시 시전                               |
| Z                                  | 연쇄 번개 즉시 시전                            |
| 두 손가락 Tap                      | 스팀팩                                         |
| PC 좌우 마우스 동시 클릭           | 스팀팩: 120ms 내 두 버튼 합류, 300ms 내 릴리스 |
| 하단 필살기 버튼                   | Gauge가 가득 차면 수동 활성화                  |
| 우측 최상단 일시정지 아이콘 / 재개 | 전투·리듬·효과를 포함한 게임 시계 정지/재개    |

짧은 jitter는 Tap이고 명확한 drawing만 Gesture 후보입니다. 실패한 Gesture는 오발동하지 않습니다. 이번 패스는 Circle/Z 제스처 인식 안정화를 포함합니다. 두 손가락 스팀팩과 PC 보조 입력은 유지합니다. 그리기 제한은 5초, Tap 제한은 300ms입니다. 느린 입력과 Z 획 정렬을 보완했으며 원의 기존 PCA·임계값은 유지합니다. 적의 touch 영역은 시각 크기보다 조금 넓습니다. 마법 HUD는 입력 버튼이 아닙니다.

기본 가우스는 Tap 1회=3점사, 발당 피해 10, 간격 110ms, 회복 380ms. 무기 상태가 발사 속도를 결정하며 입력 예약은 최대 1개입니다. 연타로 DPS가 증가하지 않습니다. 짧은 tracer/muzzle flash를 사용합니다.

스팀팩: 정상 → 강화 5초×1.5 → 탈진 1초(Primary 불가) → 회복 2초 → 정상. 강화 지속/배율은 data-driven, 회복은 정상 공격속도로 점진 회복합니다. 탈진 1초는 고정입니다. 강화 선택으로 지속 +0.5초×4, 배율 +0.1×3, 회복 −0.2초×3을 적용할 수 있습니다.

### 제스처 안정화

3초 동안 정상적인 원/Z를 그려도 기존 2,500ms 입력 제한 때문에 인식기까지 전달되지 않는 경우를 테스트에서 재현했습니다. **그리기만 최대 5,000ms로 확대**했고 Tap의 300ms 제한은 유지합니다. 브라우저가 묶어서 전달한 중간점(coalesced events)과 손을 뗄 때의 마지막 점을 보존합니다.

원의 PCA 정렬·인식 임계값은 유지하고 기존 정상 원의 다양한 크기·시작점·방향 fixture를 보강했습니다. Z는 ±20도 정렬과 ±4 sample 범위의 순서 정렬로 느슨한 획을 수용합니다. N·역Z·미완성Z·L·V·C·낙서·너무 작은 링은 거절합니다. 관련 집중 테스트 **38/38 통과**이며, 실제 휴대폰에서 보고된 인식 문제의 원인을 확정한 것은 아닙니다.

Debug의 `samples`는 필터를 통과해 인식기에 들어온 점 수이며 브라우저의 전체 pointer 이벤트 수가 아닙니다. `pathLength`는 CSS px 기준입니다. 실제 Android/iPhone에서 느린 입력·빈도 차이·다중 터치 사용감은 별도 확인이 필요합니다.

## 6. Weapon Trait와 선택

### 강화 종류와 희귀도

강화 카드의 **종류**와 **희귀도**는 독립된 축입니다. 종류는 효과가 작동하는 계통을, 희귀도는 일반·희귀·유니크·전설 등급을 뜻합니다. 희귀도 이름인 “일반”을 강화 종류 이름으로 사용하지 않습니다.

| 공식 강화 종류 | 현재 범위 | 무기 특성 슬롯 |
| --- | --- | --- |
| 기본 강화 | 기본 공격력·공격속도·치명 확률 3종 | 사용하지 않음 |
| 무기 특성 | 8종 특성과 전설 행동 강화 3종 | 8종 신규 획득만 사용: 기본 3칸, 코어로 4칸. 전설 강화는 추가 슬롯 없음 |
| 마법 강화 | 서리장·연쇄 번개 강화 | 사용하지 않음 |
| 보조 기술 강화 | 스팀팩 지속·공격속도 배율·회복 강화 | 사용하지 않음 |

전설 행동 강화인 폭주 연쇄·공성 관통포·연쇄 폭풍탄은 무기 특성 종류로 표시하되 추가 슬롯을 사용하지 않습니다. 카드 짧은 효과는 유지하고 상세 설명·일시정지에서 “전설 강화 · 추가 슬롯 없음”을 안내합니다.

**필살기 강화는 미래 분류이며 현재 강화 카드에는 없습니다.** 유물·코어는 별도 보상 계통입니다. 공식 용어는 기본 공격 / 보조 기술 / 마법 / 필살기 / 강화 카드 / 기본 강화 / 무기 특성 / 마법 강화 / 보조 기술 강화 / 유물 / 코어 / 시너지 / 진화 / 비밀 진화입니다. 스팀팩은 보조 기술의 현재 콘텐츠 이름입니다. 비밀 진화는 미래 설계이며 현재는 초관통 가우스 진화만 구현합니다.

카드는 중앙에 가로로 정렬한 정사각형을 유지합니다. 시각적 우선순위는 **큰 아이콘 → 이름 → 짧은 효과 → 종류 배지 + 희귀도 텍스트 → 현재/다음 레벨**입니다. 종류 배지는 계통을 설명하고 희귀도 텍스트는 별도로 표시합니다. 전체 효과 설명은 aria/title에 보존합니다.


현재 기준은 이 문서입니다. GDD v0.1은 과거 문서로 원문 보존합니다. 플레이어 문구는 한국어, 내부 ID는 영어입니다.

- 처치 XP Grunt/Runner 1, Shield 3. 다음 요구 XP는 `8+6(L−1)+2(L−1)²`; 초과 XP·밀린 선택을 보존합니다.
- **기본 강화·마법 강화·보조 기술 강화는 무기 특성 슬롯을 사용하지 않습니다.** 일반 등급 기본 강화는 공격력 +15%, 공격속도 +6%, 치명 확률 +5%p의 3종이며 각각 최대 5회입니다. 치명타 피해 배율은 ×1.75 고정입니다. 스팀팩 강화 3종의 종류는 보조 기술 강화이며 희귀도는 일반입니다.
- **속사 특성은 제거하고 기본 강화 공격속도로 통합했습니다.** 기본 3점사는 유지하고 발사 간격·점사 회복을 함께 줄입니다. 기본 치명타는 특성 없이 확률 5% / 고정 피해 ×1.75입니다.
- 특성 8종: **관통·도탄·다중탄·폭발탄·치명타·분열탄·중량탄·처형탄**, 각각 Lv1~5. 기본 3종, 전술 확장 코어로 최대 4종. 꽉 차면 미보유 특성만 제외하며 기본 강화·마법 강화·보조 기술 강화는 계속 선택할 수 있습니다.
- 새 특성은 희귀. 각 레벨의 희귀도는 효과 행에 명시하며 현재 Lv1/2/4 희귀, 강한 Lv3/5 유니크입니다. 희귀도와 레벨은 별도 데이터이며 EPIC의 한국어 표시는 **유니크**입니다. 전설 효과는 유지합니다.
- 일반/희귀/유니크/전설 기본 가중치 10/4/1/0.25, 투자 tag당 +8% bias(최대 ×1.6). 여기에 8종 무기 특성 카드만 선택 가중치 ×2를 적용해 등장 비중을 높입니다(prototype tuning). 투자 계열의 첫 슬롯을 보장하지 않습니다. 행운 코어·유물은 희귀도 가중치에 곱해집니다. 후보 구성에 따라 실제 확률은 달라집니다.
- 유효한 비MAX 후보 중 중복 없이 최대 3장, Reroll 없음. 강화 카드는 중앙 가로 정사각형이며 큰 아이콘·이름·짧은 효과·종류 배지와 희귀도 텍스트·현재→다음 레벨 순서로 표시합니다. 전체 설명은 aria/title에 보존합니다. 유물 선택도 중앙 가로 카드 배치를 유지합니다.
- 치명타 특성은 치명 확률 기본 강화와 별개로 Lv1부터 충격파, Lv3부터 메아리를 만듭니다. 분열탄은 한 세대만 분열, 중량탄은 피해·밀침과 충격파, 처형탄은 생성 당시 최대 HP 기준 저체력 적 직격 처형입니다. 처형 충격파는 재귀 처형하지 않습니다.
- 전설 폭주 연쇄는 **공격속도 4회**, 공성 관통포는 관통 Lv4, 연쇄 폭풍탄은 도탄 Lv4부터 후보입니다. 특성 Lv5에 전설은 필요하지 않습니다.

## 7. 시너지 / 진화

Recipe는 `traits/relics/magic/upgrades`의 조건을 데이터로 조합하고 공통 판정으로 평가합니다. 특정 Marine 코드에 조건을 하드코딩하지 않습니다.

| 시너지    | 조건              | 실제 행동                                      |
| --------- | ----------------- | ---------------------------------------------- |
| 심층 폭발 | 관통≥1 + 폭발탄≥1 | 관통 과정의 적중 지점마다 폭발                 |
| 살상 도탄 | 도탄≥1 + 치명타≥1 | 치명타 피해를 도탄에 이어가고 치명타 도탄 +2회 |
| 탄막 폭풍 | 공격속도≥3 + 다중탄≥1 | 매4번째 발사에 온전한 피해 추가 동시탄2발      |

첫 진화: **관통 Lv.4 + 공성 증폭기 Lv.3 → 초관통 가우스 (Hyper Gauss)**. 추가 관통 +3명, 폭×1.6, 굵기8 청록 tracer. 조건 전에 발생하지 않고 Run당 중복 발동하지 않습니다. 짧은 중앙 진화 알림만 표시합니다. Trait+Trait, Trait+Relic, Magic+Relic, Trait+Magic+Relic 조건을 같은 데이터 형식으로 확장할 수 있습니다.

## 9. 마법 / 필살기

- 서리장: 전역 이동속도 ×0.5, 7초, 대기 30초. 신규 적도 느려지고 성벽 공격·spawn·Primary·다른 대기는 느려지지 않습니다. 감속 +6%p×5(최저 이동배율 0.25), 지속 +0.8초×5, 서리 tag 6 이후 파쇄 즉시 피해 30.
- 서리 균열: 서리 중 기본 피해 +15%×3. 빙결 파편: 서리 중 처치 지점 반경 130에 피해 35×3, 한 판정 최대 8중심·한 세대·대상 중복 피해 없음.
- 연쇄 번개: 연결 반경 360, 최대 30명, 각 피해 75, 대기 24초. 대상 +2×5 / 피해 +18×5 / 거리 +40×4. 번개 tag 6 이후 분기 폭풍은 미적중 3명에게 60% 피해.
- 처치 연쇄: 번개 처치당 추가 연결 +2×3, 한 시전 추가 대상 상한 12. 낙뢰 충격: 6번째 연결 적중마다 반경 150의 미적중 적에게 번개 피해 50%×2, 재귀·중복 타격 없음.
- 공용 치명 피해 강화와 마법 대기시간 강화 카드는 없습니다. 강화 획득으로 이미 진행 중인 마법 대기를 초기화하지 않습니다. 빈 전장 시전도 대기를 소모합니다.

## 11. 결과 / 성능 / 성공 기준

현재 패스의 `npm.cmd run check`: 29개 파일 / 143 tests, TypeScript·Vite build 통과. 제스처 집중 테스트는 38/38 통과했습니다. 번들 크기 1,291.06 kB / gzip 348.35 kB의 기존 500 kB 경고는 남아 있으며, 테스트 통과가 실제 모바일 인식률·재미·180마리 성능 승인을 의미하지 않습니다.

현재 결과는 생존시간, 처치, 레벨, 성벽, 특성/강화/유물/진화를 한글로 보여주고 재도전합니다. 영구 재화나 기록 저장은 없습니다.

모바일 Horde Fantasy는 핵심 요구입니다. 실제 기기에서 FPS, frame spike, memory, 입력 반응을 측정한 뒤 pooling/atlas/공간탐색/VFX budget/먼 적 저빈도 갱신을 선택합니다. cap300은 검증된 성능 예산이 아닙니다. 전용 stress test는 별도이며 과도한 조기 최적화를 하지 않습니다.

성공은 테스트 통과만으로 선언하지 않습니다. Tap/자동·수동 타겟/마법/스팀팩의 사용감, Soft Lane 판단, 선택 후 변화, 후반 쓸어버리는 성장, 5분 재도전 욕구와 실기기 성능을 사용자 플레이테스트로 평가합니다. 실패하면 Final Art/Audio 투자 전 전투 설계를 수정합니다.

## 12. 개발 원칙

Phaser + TypeScript + Vite, 모바일 웹 우선. balance/recipe/content와 pure logic을 렌더링·입력에서 분리하되 미래 Godot를 위해 과도하게 추상화하지 않습니다. Godot 이전 시 GDD/수치/콘텐츠/공식/아트는 재사용하고 scene/input/render는 다시 구현할 수 있습니다.

Codex는 저장소·구현·테스트·디버깅·빌드·profiling, 설계 협업은 GDD/계획/밸런스/아트 명세를 중심으로 합니다. 작고 승인된 작업 단위로 진행하며 이번 변경은 기존 Milestone12 브랜치에서 commit/push, 사용자 플레이테스트 후 merge 판단. 다음 Milestone 자동 진행 금지.

관리자 Balance Editor, Spawn Console, Run/Time Scale, DPS/Recipe/Wave 도구는 반복 조정이 필요해질 때 도입합니다. 지금은 data 파일과 D Debug Overlay(기본OFF)로 확인합니다. 없는 기능용 GUI/백엔드/최종아트는 추가하지 않습니다.

## 13. 보존한 미래 설계 — 현재 미구현

- **정식 Stage:** 약 15분과 중단 Resume, 여러 encounter/Elite/Unique/Boss. Stage 시작 전 적 종류와 대략적 비중을 공개하되 정확한 순서와 숫자는 숨깁니다. 이전 Stage도 다른 캐릭터/무기/마법/진화/도전으로 재플레이할 가치가 있어야 합니다.
- **마법 슬롯:** 정식 시작 1 → 영구 해금 2 → 최대 3. Gesture는 spell이 아닌 slot에 연결하며 ○/Z/│가 예시입니다. 현재 Prototype은 2종 고정. 미래 Targeted Cast는 Gesture 뒤 위치 Tap이며, Meteor와 마법별 2갈래 전문화는 미구현입니다.
- **Reroll:** 정식 Meta 해금 0 → 1 → 2 → 최대 3/Run. 현재는 없습니다.
- **Recipe 발견:** 진화/시너지/Secret Evolution의 조건은 Hint 전부터 존재합니다. Hint는 권한 해금이 아닌 발견 도움입니다. 캐릭터/무기/마법/유물 발견, Stage/Challenge/Near Miss가 미래 힌트 원천입니다. 발견 후 Codex에 조건을 영구 기록하지만 매 Run 다시 충족해야 합니다. Secret Hint/Near Miss/Codex는 미구현입니다.
- **Run reset:** 레벨/XP/특성/임시 확장/강화/유물/진화. **영구 Meta 후보:** 캐릭터, Weapon Variant, 마법/슬롯, Reroll, Recipe 발견, Mastery, 재화, Stage, Challenge.
