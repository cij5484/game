## 2. 이전 HUD 패스에 적용한 판단

- **상단 빌드 바:** 얇은 반투명 띠 안에 `기본 강화 합산 → 무기 특성 → 유물 → 확장 코어`를 간격·구분선으로 묶는다. 획득 항목만 표시하고, 각 아이콘 내부에 레벨/합산 수를 둔다. 기본 강화 합산은 해당 계열에 투자한 랭크 합계이며 개별 효과의 단일 레벨로 오해되지 않게 접근성 설명을 제공한다. 빌드 바는 읽기 전용이다.
- **하단 통합 성벽 HUD:** 기존 성벽을 더 두껍게 사용해 HP, 레벨/XP, 시간과 스팀팩·장착 마법·필살기 상태를 모은다. 중앙 전투 공간에 별도 큰 패널을 추가하지 않는다. 스팀팩와 마법은 상태 표시이며 기존 터치·제스처 입력을 유지한다. 필살기는 준비됐을 때 수동 버튼이다.
- **원형 진행 표시:** 아이콘 중심은 유지하고 바깥 진행을 12시 시작·시계방향으로 통일한다. 마법은 재사용 준비도, 필살기는 실제 충전도, 스팀팩는 현재 단계의 진행도를 사용한다. 스팀팩 `강화/탈진/회복/준비`, 마법 `대기/준비`, 필살기 `충전/준비`를 짧은 한국어 문구로 보완한다. 색만으로 상태를 구분하지 않는다. 이 원형 표현은 레퍼런스의 확인된 기능이 아니라 **사용자 요청을 구현하기 위한 프로젝트 설계**다.
- **일시정지:** 우측 최상단에 고정하고 빌드 바가 버튼 영역을 침범하지 않게 한다. 시각 아이콘이 작더라도 터치 영역과 한국어 접근성 이름은 확보한다.
- **세로 모바일:** safe-area 안에 정보·버튼을 두고 배경은 화면 전체를 채운다. 좁은 폭에서도 아이콘 레벨과 필살기 조작을 읽을 수 있게 유지한다. 툴팁 hover에 필수 정보를 의존하지 않으며 긴 설명은 선택·정지 화면에서 읽는다. 최대 보유 상태에서 겹침·가로 넘침이 없는지 확인한다.

## 3. 경계와 확인 항목

기존 `GAME_GDD_v0.2.md` §4의 “상단 Battlefield 전용 / 유물 하단 배치”는 이번 상단 빌드 바 요청에 맞춰 본 작업의 문서 담당자가 갱신한다. 한국어 우선, Full-Bleed, 독립 HUD root, 마법 표시 비버튼, 필살기 수동 발동은 유지한다.

확인할 장면은 초기 빌드, 모든 보유 슬롯과 일반 강화가 채워진 빌드, 쿨다운 0/중간/완료, 스팀팩 각 단계, 필살기 준비, 일시정지·재개, 좁고 긴 세로 화면이다. 레퍼런스 조사는 가독성 방향의 근거이며 실제 기기 터치 품질·재미·밸런스 승인으로 취급하지 않는다.

### 적용한 역할 구분

- **기본 강화:** 공격력·공격속도·치명 확률. 현재 사용자가 조정한 수치를 보존한다.
- **무기 특성:** 적중 경로/분포, 상태, 집중 사격, 국지 제어, 사격 리듬을 바꾸는 9종. 분열탄은 도탄과 겹치고, 중량탄은 수치 중심이며, 치명타는 기본 강화와 겹치므로 특성 후보에서 제거한다.
- **유물:** 기본 공격↔마법↔스팀팩↔성벽을 사건으로 연결하는 8종. 희귀도 조작은 행운 코어에 남긴다. 회복·연장·복제에는 상한과 종료 조건이 있다.
- **자연 상호작용 / 시너지 / 진화 / 비밀 진화:** 기본 효과의 동시 적용 / 조합이 여는 새 행동 / 높은 투자로 시스템 변형 / 복잡한 숨은 고급 조합. 마지막 층은 미래 설계이며 현재 구현이라고 표시하지 않는다.
- **조작 활용:** 표식은 같은 적을 재지정해 집중할 때 가치가 생기고, 제압은 성벽 앞 특정 전선을 밀며, 냉각을 위한 사격 쉼과 서리 Gesture의 시점이 의미를 갖는다. 자동 타겟에서도 작동한다.
- **인지와 성능:** 처음 활성화할 때 짧은 한국어 알림, Build Bar의 작은 기호, 일시정지의 조건/효과로 연결한다. 공격 이벤트의 대상 수·전염 깊이·복제 큐·표시 효과를 제한한다. 300마리 논리 stress 검증과 실제 모바일 FPS 검증을 구분한다.

위 적용은 재미의 가설이다. 레퍼런스의 상업적 성공이 우리 게임의 밸런스를 증명하지 않는다. 실제 Lv별 수치·12종 시너지·발동 상한은 [GDD v0.2](GAME_GDD_v0.2.md)와 현재 data를 기준으로 확인한다.

### 필살기 제스처 후보 판단

| 후보 | Circle/Z와의 구별 및 손가락 부담 | 결정 |
| --- | --- | --- |
| 닫힌 삼각형 | 한 손가락으로 가능하지만 폐곡선이라 ○와 닮고3변·마감점이 필요 | 제외 |
| loop | ○와 가장 가깝고 불필요한 회전/마감 판단이 늘어남 | 제외 |
| 옆 chevron > | 2획이지만 방향 혼동과 불완전Z의 일부 경로와 비슷함 | 제외 |
| 아래 꼭짓점 V | 상단의 분리된 끝점과 아래 한 번 꺾임, 닫힘·세 번째 획 불필요 | **선택**, 양방향 허용 |

이 비교는 프로젝트 설계 판단이며 레퍼런스 게임이 V 필살기를 사용한다는 주장이 아니다. Gauge 미충전이면 인식 함수가 즉시 거절하고, 준비 상태에서도 기존○/Z를 거절하는 테스트를 둔다. 코드와 힌트는 같은 정규화V 경로를 공유한다. 크기·좌표 위치·샘플밀도·작은 손떨림·기울기를 허용하는 논리 테스트와 실제 휴대폰 성공률은 구분한다.

마법/스팀팩 아이콘은 Gesture와 같은 능력·대기시간을 사용하는 fallback 버튼이다. 필살기만 **아이콘=경로 힌트 / 준비된V=즉시 발동**으로 분리한다. 기존 Rhythm·등급·슬로모션은 폐기하며 항상 고정된 강력한 억제 사격을 제공한다.
